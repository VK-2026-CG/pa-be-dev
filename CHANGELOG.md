## 2026-10-02
- Persistency (PERSISTENCY_CY/Y1/Y2) no longer gets a prior-year comparison in the dashboard list (`metricList`) in Mongo mode: no `comparison`/`delta`, and the prior-year `my_persistency` row is not queried for it. Persistency is a yearly measure (the dashboard card design shows the value with no delta). `metricDetail` is unchanged (persistency still returns a comparison only when a real prior row exists). The card's "Persistency is calculated yearly" caption is frontend copy and is not part of this change (open item OQ-59). Other metrics are unchanged.
- Contract documentation for the above: C2 is now `1.9.1` (`vendor/spec/insights.v1.yaml`, refreshed with `npm run sync:specs`). `listAgentMetrics` documents when `MetricSnapshot.comparison` is populated — a `collected` value plus a day-aligned prior-year row; omitted with no such row (never fabricated) and for `PERSISTENCY_*`; `FLAT`/`NEUTRAL` with a zero magnitude when a prior-year row exists but the metric leaf is null, matching `metricDetail`. Description-only, no schema change: `comparison` was already optional on `MetricSnapshot` and already in the operation's 200 example, so no code, type or fixture change was needed. The sync also brings the vendored copy from `1.8.0` to `1.9.1`, picking up the `getAgentMonthlyHistory` addition that landed in spec `1.9.0` but had only been hand-patched here.
- Dashboard "vs last year" delta restored in Mongo mode. `PerformanceSource.metricList` now attaches `comparison` (a domain `Change`: direction, sentiment, `pct`/`pp`/`abs`) to every metric that has a value, so `GET /api/bff/v1/performance/dashboard` cards carry `delta` again (previously only the memory source did; the BFF composer already maps `comparison` to `delta`, so it needed no change). It reuses the `metricDetail` logic (`comparisonFor`): same month one year back, closest declared as-on day not after the current one, so a card's percentage equals the detail screen's. Applies to every mapped metric across `my_production`, `my_mapa` and `my_persistency`; reads are cached per request, so at most one prior-year query per collection. No day-aligned prior-year row means no `delta` (never fabricated). Persistency gets no zero stand-in. Validation: `test/performance-source.test.ts` "metricList (dashboard) populates items[].comparison" now passes; typecheck reports no `src` errors; the file still has pre-existing failures unrelated to this change (13 of 48 in this run, including two `metricDetail` prior-year/auth tests).

- ARVIJ-1450 Team Historical Data, backend half (S-P4-03 v2.0.0; AC-P4-03-15..31). New domain read `GET /insights/v1/agents/{agentId}/monthly-history?from=YYYY-MM&to=YYYY-MM[&aggregation=Personal|DirectUnit|Group]` (`getAgentMonthlyHistory`, `DataSource.monthlyHistory`): month-level `ptd.<metric>.mtd` values from BOTH databases (`pa_performance_PAMB-dev`, `pa_performance_PBTB-dev`) and both collections (`my_production`, `my_mapa`), one record per (period, source, aggregation), ascending by period, source, aggregation; months without a row are omitted and there is no aggregation fallback. When several rows exist for a month the month-end-flagged row (`isMonthEnd` y/yes/true/1) wins, else the greatest declared as-on day (`period.asOnMonthDay` as Int, Date or string), else the greatest `asOnDate`, then `id`/`_id` descending (decision D2). Whitelist projection, `maxTimeMS` 30 s, one transient retry, sanitized `503 INS-5030` (cause only), `400 INS-4000` for a bad/over-48-month range or aggregation; identity handling is the `series` route's (`ownIdentityOnly` in source mode). Each part's `asOnDate` is the in-month as-on date (period year-month + declared `period.asOnMonthDay`, the month's last day when undeclared), never the `asOnDate` load watermark (dashboard AC-PA-DIRECT-29 rule); the watermark is only a D2 tie-break, and the BFF `meta.asOfDate` (newest part date) is therefore in-month too. Malformed rows are skipped and counted in the log, not returned. Memory source: deterministic stub (2023-01..2026-06 closed + partial 2026-07, both sources, three aggregations). See `docs/monthly-history-source.md` (selection rule, mapping, privacy, and the recommended `{agentId, entity, period.year, period.month}` index, which this change does NOT create; `db:setup` is untouched).
