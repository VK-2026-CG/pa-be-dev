# Changelog

## 2026-10-01
- Added `npm run db:seed:team-mock` (`scripts/seed-team-hierarchy-mock.ts`): a development-only seed of a nested Team Drilldown hierarchy (AM → UM → UM1 → UM2 → agents, 19 members) under a synthetic AM `MCKAM001` in `pa_performance_PAMB-dev`, with cloned metric rows so cards, KPI tiles and the agent self view have data. Existing AM data is flat, so team icons and nested drill-down could not be tested against Mongo. Dry run by default, insert-only on `--apply` (one transaction, conflicts abort), everything on the reserved `MCK` prefix, `--remove --apply` deletes exactly the seeded documents; no real record is modified. Template AM is chosen automatically (complete newest-period rows, non-zero TPC/PTPC, schema-valid; skipped candidates are reported). Added `test/team-hierarchy-mock.test.ts` (drives the real `PerformanceSource` through every level and the D-14 depth rule) and a section in `docs/team-drilldown-hierarchy-source.md`. The runtime still never writes `my_agent_hierarchy`.
- Metric Detail (MongoDB source) now builds `barComparison` for Case Count, Productivity, New Recruits (grouped, abs-change chip) and Manpower (stacked: existing agents = total − new recruits, from `my_mapa`), using the same period rules and prior-year rows as the comparison; a missing prior row gives the neutral zero prior. Persistency now returns a prior-year `comparison` only when a real prior row exists (never a zero stand-in). Catalog: `barComparison` capability added to CASE_COUNT and PRODUCTIVITY (Figma note: same layout as New Recruits). Updated 3 BFF tests and 1 source test; backend suite unchanged at the 18 pre-existing failures.
- The 503 `INS-5030` "Identity source unavailable" message now carries a sanitized cause in brackets — `(network)`, `(authentication)`, `(timeout)` or `(other)` — so it can be diagnosed from the browser's Network tab. Only the category is exposed; driver messages, hosts and credentials never are. Shared `classifyMongoError` helper also feeds the server log.
- Mongo timeout raised from 8 s to 30 s: `PERFORMANCE_READ_TIMEOUT_MS` (query `maxTimeMS` and dedicated-connection server selection), the shared connection's `serverSelectionTimeoutMS` and the preferences store now share that one constant. Docs and the spec text (C1/C2, direct-mock-profile, SPEC-2026-005) updated from "eight-second" to 30-second. Note: a slow or blocked connection now takes up to 30 s to return 503 instead of 8 s.
- Hierarchy reads (identity lookup on every dashboard call) retry once after a transient connection error (dropped socket, server-selection failure) before returning 503 `INS-5030`; timeouts and auth errors are not retried. Retries are logged.
- Added `npm run db:diagnose [agentId]`: checks Atlas reachability, the PAMB/PBTB hierarchy read and the preferences database read/write (one marker document, removed again), and prints which step fails and why, without credentials. For debugging INS-5030 on a machine.
- Identity/hierarchy read failures (503 `INS-5030` "Identity source unavailable") now log a sanitized cause server-side — error class, driver code and a category (timeout, network/server-selection, authentication) — instead of swallowing it. Driver messages, hosts and credentials are never logged. The HTTP response is unchanged.
- Customize Metrics preferences are persisted in MongoDB (database `MONGODB_PREFERENCES_DB`, default `pa-performance-preferences-coedev3`; collection `metrics_preferences`) instead of process memory, so they survive restarts. One document per `_id: { tenant, agentId, scope }` with `priorityMetricCodes`, `focusMetricCodes`, `updatedAt` (C1 §5 shape); writes are upserts. Store failures return a sanitized 503 `INS-5030`. The offline memory engine and tests keep an in-memory store.
- Specs are reference material, not gates: rewrote AGENTS.md, CLAUDE.md, Copilot/skill/workflow docs and handoff docs so no spec status, approval, handoff or receipt blocks development; security, authorization and environment safeguards unchanged. Retired handoff scripts marked as history.
- Viewing a downline member with no metric rows (S-P4-01 viewing mode) returns the viewing dashboard with EMPTY cards (no values, not zero-filled) instead of a 404. The member's missing milestones/recommendations are no longer reported as failed sections. Outside viewing mode, no rows still returns 404.
- Team Drilldown KPI tiles (unfiltered) now come from the leader's own `my_mapa` team row (DirectUnit, or Group for teamView=GROUP): the same Manpower / Activity Ratio / Productivity / Average Case Size as the Team dashboard. Before, the tile was a hierarchy head count (e.g. 18 vs 9) and the other tiles were blank. With a search/level/badge filter, MANPOWER counts the matching members' organisation and the other tiles have no value.
- Test fake DB now matches array fields like Mongo (any element equals the value).
- Team Drilldown (S-P4-07) now reads the caller's team from `my_agent_hierarchy` in Mongo mode instead of always returning an empty list. Direct reports come from the newest snapshot's `subtree.scopeProfileIds` (PAMB first, PBTB when the root is absent). The leader's own ID, which UM/agent snapshots list first, is skipped. Card TPC/PTPC come from `my_production`; badges, goal status and photos still have no source (OQ-79) and are omitted. MANPOWER counts the filtered members' organisations; the other KPI tiles stay value-less. The subteam drawer, member lookup and the selected-member preview enforce D-14 visibility (P3 direct team, P2 whole downline) from the same hierarchy.
- Hierarchy reads are no longer gated by `INSIGHTS_HIERARCHY_SOURCE`, which is now ignored. Tier mapping is case-insensitive (`Agent`/`agent`/`UM2` previously failed as malformed). An agent listed as a reportee without its own snapshot resolves as a P4 identity so leaders can open its dashboard. `getAgentOrganization` skips the self-reference instead of failing as a cycle; real cycles still fail.
- Team Drilldown query performance: member TPC/PTPC now come from one batched `$in` read per metric collection. Previously each member cost up to six reads (three collections, plus a fallback without aggregation). The MANPOWER walk and the caller's reporting-date read now run concurrently with it. Hierarchy roots are memoized for 60 s, and IDs without a document are not looked up twice. Against dev Mongo, one request dropped from 116 queries / ~2.3 s to 7–8 queries / ~0.15–0.75 s. The remainder is collection scans: the source collections carry only the `_id` index.
- Validation: verified against `pa_performance_PAMB-dev` (1136911 → 18 members; 1002809 → 25). `npx vitest run`: 232 passed, 18 failed. The same 18 fail on the previous build (`dist/`): identity fixtures lacking hierarchy rows, prior-year comparison, import `schemeType`, AC-ORG-01 dedupe and the team-mock-overlay proxy. Typecheck errors in `src/data/values.ts` and `src/types.ts` are also pre-existing.
